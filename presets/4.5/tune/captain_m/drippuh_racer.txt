# Do NOT copy version-specific bits across:
#   - #$ INCLUDE paths (each points at its own firmware's defaults)
#   - #$ FIRMWARE_VERSION
#   - settings renamed between versions (e.g. simplified_dmax_gain in 4.5 vs

#   - debug_mode (GYRO_SCALED in 4.5, MULTI_GYRO_SCALED in 2025.12+)
#
#
# --- CLI GOTCHAS (learned the hard way, do not re-derive) ---
#
# 1. Channel numbering differs per command:
#      aux / vtx   -> AUX-RELATIVE   (7 = AUX8, 11 = AUX12)
#      rxfail      -> ABSOLUTE       (0-3 are the AETR flight channels, so
#                                     15 = AUX12, and AUX8 would be 11)
#
# 2. The mode number in an 'aux' line is Betaflight's PERMANENT ID, not the
#    position in the boxId_e enum (that enum is reordered between releases).
#    By permanent ID: 0=ARM, 1=ANGLE, 13=BEEPER, 26=BLACKBOX, 27=FAILSAFE,
#    28=AIR MODE, 29=3D DISABLE, 35=FLIP OVER AFTER CRASH, 36=PREARM.
#    Look these up in src/main/msp/msp_box.c rather than guessing.
#
# 3. aux range bounds must be multiples of 25. rxfail values are stored in
#    25us steps from a 750 floor, so 875 and 1000 are exact, 988 is not.
#
# 4. Run 'npm run verify' before committing.
#
# These lines start with a single '#', not '#$', so the Betaflight
# Configurator ignores them and they are not shown to the user.

    #$ OPTION BEGIN (UNCHECKED): Cut VTX power when in failsafe
        # There are 2 options here:
        #
        # Option 1: Rely on the vtxtables and make it so that AUX 12 can 
        # trigger the vtx can go into powermode 0mW. This is done be setting:
        #    vtx 0 11 0 0 3 900 1300
        #    rxfail 15 s 1000
        # This says: "vtx goes into mode 3 (0mW) when AUX 12 (channel 11) has
        # a value between 900 and 1300. The second line says when we are in
        # failsafe, (s)et 15 (AUX 12) to value 1000, thus driving the VTX to 
        # 0mW when in failsafe.
        # See: https://www.youtube.com/watch?v=oagiNwXK8uE
        # See: https://www.youtube.com/watch?v=nRM_bXJ4sWQ
        #
        # Option 2: make the 9v BEC switchable so we can physically turn
        # off the power to the VTX. You can do this as follows:
        #     resource PINIO 1 E03 
        #     set pinio_config = 129,1,1,1
        #     set pinio_box = 27,255,255,255
        # This creates a new IO pin number 1 against pin E03. Then it sets the config 
        # to 129 which means that by default the pin is the inverted output (in our case 
        # we will tie it to FAILSAFE, so whenever FAILSAFE is on (1, high), it will set 
        # the pin to the invertion (0, low) and a LOW value on the BEC means no power to VTX)
        # The pinio_box = 27 means look at failsafe (which is 27, see the docs)
        # Note that there are 4 pins in betaflight, and we only use the first one, hence we
        # keep the default values of 1 and 255 on the other pins
        # See: https://betaflight.com/docs/wiki/guides/current/Pinio-and-PinioBox
        # See: https://www.youtube.com/watch?v=dnOV5_n3y4c
        #
        # Which option you choose depends on the use case a bit. Option 1 is faster
        # because the VTX stays powered on, but it still heats up the VTX, even though
        # it's much slower than when it's properly turned on, but it still uses 0.5W
        # The BEC option really cuts the power to the VTX which is better for heat as 
        # there is literally no power, there is no heat, but when you turn the VTX on
        # it will take around 2 seconds too boot up, so take that into account.
        #
        # We are going with option 2 today:
        resource PINIO 1 E03 
        set pinio_config = 129,1,1,1
        set pinio_box = 27,255,255,255
    #$ OPTION END

# --- SWITCHABLE QUADS ---
# Select which quad this is. Each quad listens on its own AUX8 band, so a single
# radio model can be pointed at any one of them by changing the AUX8 value.
#
# Each option sets the craft name and puts the quad into FAILSAFE (mode 27)
# whenever AUX8 is NOT in this quad's band, so pointing the radio at a different
# quad keeps this one on the ground. Failsafe cuts the motors.
#
# Mode 27 is the FAILSAFE *permanent ID* used by the CLI, which is a different
# numbering from the internal boxId enum. The aux channel argument is
# AUX-relative, so 7 = AUX8.
